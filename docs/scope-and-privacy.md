# Scope and privacy

## Included

- Product and architecture overview.
- Generalized data relationships.
- Engineering challenges and implementation decisions.
- Technology choices stated at a high level.

## Excluded

- Application source code, build output, and dependency lockfiles.
- Credentials, environment files, database dumps, and personal or customer data.
- Production hostnames, deployment identifiers, and screenshots from live operations.
- Measured ROI claims that have not been verified.

## Before publishing identifying details

Confirm that the client agreement permits public portfolio use. If it does, the case study can name the customer and link to an approved public product page. If it does not, retain the generalized description, omit the live URL, and use generated data with customer branding removed in any future images.

## Adding visual evidence

Only add screenshots or GIFs after confirming permission. Use generated or anonymized data, remove names and contact details, and check that logos, URLs, venue layouts, staff schedules, and sales figures are approved for public use. Do not use synthetic images that imply they are actual product screenshots.

## Adding code excerpts

Code excerpts are not included. If permission is granted later, add only isolated, generic examples that do not expose customer-specific logic, identifiers, credentials, or operational data. Suitable candidates may include a generalized migration workflow, a provider-neutral integration adapter, or a small reusable UI pattern.
